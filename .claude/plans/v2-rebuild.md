**מטרה:** מערכת שבודקת אילו מניות עומדות בכמה שיותר קריטריונים של הגורואים (שיעורים 3–6), מודדת
כמה כל אחת היא הזדמנות קנייה, ומציגה את זה בדשבורד ויזואלי שרץ אונליין ב-Railway. הסריקה

**Done when:**

- ריצה מתוזמנת אחת לפחות רצה מעצמה, ו"הרץ כעת" עובד; מספר הימים נשמר ונשרד restart.
- כל קריטריון מהשיעורים ממומש לפי הגדרה מתועדת, עם ערך, סף, סטטוס וציון; כל סטייה מהשיעור
  היא החלטה רשומה ב-ROADMAP.
- כל ממצא ב-[v2-audit.md](v2-audit.md) טופל או הוחלט במפורש שלא לטפל בו.

**אושר ע"י המפתח:** ארכיטקטורה A (שירות אחד) — 2026-11-05. התוכנית המפורטת — ממתינה.
**הרשאה:** למפתח אין דרישה לשמור על המבנה הקיים; מותר לערוך, להעביר ולמחוק כל קובץ (2026-11-05).

## 1. עקרונות

1. **ביקורת קודם, קוד אחר כך.** ההנחה היא שקוד ותיעוד עלולים להיות שגויים. כל צעד מתחיל
   באימות ההנחה שלו מול הקוד והנתונים.
2. **הגדרה אחת לכל קריטריון.** כל קריטריון מוגדר פעם אחת: מזהה, גורו, שיעור-מקור, נוסחה, סף,
   כיוון. הדוח, הציון והדשבורד נגזרים מאותה רשומה.
3. **הספים בקובץ אחד.** כל קונפליקט בין ה-PDF לסיכום הוא וריאנט בקובץ הספים, עם ברירת מחדל
   שנבחרה ב-ROADMAP.
4. **נתונים חסרים ≠ עובר.** קריטריון שאי אפשר לחשב הוא `NA`, לא נספר בציון, ומוצג ככזה.
5. **המחיר הנוכחי לתמחור, השנים המלאות ליציבות.** מכפילים ושווי שוק — מעמודת `Current`.
   ממוצעים ומגמות — מ-5 שנות FY.
6. **הסריקה והאתר מופרדים בקוד,** גם אם רצים באותו תהליך: האתר קורא רק מה-DB.

## 2. ארכיטקטורת יעד

שירות Railway אחד, Docker על בסיס האימג' הרשמי של Playwright ל-Python:

```
FastAPI (uvicorn) ── מגיש את הדשבורד, API ל"הרץ כעת" ולסטטוס
   │
   ├── APScheduler (בתוך התהליך) ── בודק כל 15 דק' אם עברו N ימים מהריצה המוצלחת האחרונה
   │
   └── Run (משימת רקע אחת בכל רגע — נעילה ב-DB)
         login (Playwright headless) → screener → financials (httpx) →
         classify → criteria → scores → כתיבה ל-SQLite
                                                   │
                                Volume של Railway: /data
                                  ├── app.db (SQLite)
                                  ├── runs/<run_id>/<SYMBOL>/*.csv
                                  └── cookies.txt
```

## 3. מודל הציון (ברירות מחדל — ר' החלטות D8, D9)

**לכל קריטריון:** `PASS` / `FAIL` / `NA` + `strength` בין 0 ל-1:
- קריטריון עם סף מספרי: עובר עם מרווח ≥20% מהסף → 1.0; עובר בפחות → 0.75;
  נכשל בפחות מ-20% → 0.25; נכשל מעבר → 0. (שיעור 3: "מרווח ביטחון של כ-20% על כל סעיף".)
- קריטריון השוואתי (פיוטרוסקי "השנה > שנה שעברה"): 1 או 0.

**לכל גורו:** ממוצע ה-strength על קריטריונים שאינם NA, ו**כיסוי** = כמה מהם חושבו.
כיסוי מתחת ל-60% → "אין מספיק נתונים", והמניה לא מדורגת אצל אותו גורו.

**איכות** = ממוצע ציוני הגורואים (סינון, גראהם, פישר, פיוטרוסקי), משקל שווה.

**הזדמנות** = חציון מרווחי הביטחון שרלוונטיים לסיווג, כולם במחיר הנוכחי:

| רכיב | נוסחה | חל על |
|---|---|---|
| מספר גראהם | `1 − √(P/E × P/B ÷ 22.5)` | לא-טכנולוגיה, EPS>0, הון עצמי>0 |
| מכפיל הוגן | `1 − P/E ÷ P/E הוגן` (15; טכנולוגיה 25) | EPS>0 |
| מול ההיסטוריה | `1 − P/E נוכחי ÷ חציון P/E ב-5 שנים` | כולם עם 5 שנים חיוביות |
| מכפיל מכירות | `1 − P/S ÷ סף פישר` (0.8 / 1.5) | לא-טכנולוגיה |

**מועמדת לקנייה:** איכות ≥ 0.7 וגם הזדמנות ≥ 20%. שני הספים ניתנים לשינוי בדשבורד.

## 4. שלבים

כל שלב מסתיים ב-gate ירוק (`uv run ruff check . && uv run pytest -q`) ובקומיט נפרד.
השלבים מפורטים כמשימות ב-[ROADMAP](../ROADMAP.md). כאן — הסדר וההיגיון.

### שלב 0 — יסודות (לא תלוי בהחלטות)
- **A1** טיפול בשינויים הלא מקומטים (D0), ענף `v2`, pytest + ruff, gate.
- **A2** fixtures: הקפאת CSV של ~8 מניות שמייצגות מקרים (טק, תעשייה, פיננסים, שנת הפסד,
  `BRK.A`, חסר מו"פ, P/E גבוה) + טסט "תמונת מצב" של התוצאות הנוכחיות — בסיס להשוואה.
- **A3** ניקוי: מחיקת קוד מת (X1–X6), תלויות שלא בשימוש (X8), הוצאת קבצים מיוצרים מ-git (X9).
- **A4** שלד החבילה `value_scanner/` + `settings.py` (נתיבים אבסולוטיים, env), `.env.example`.

### שלב 1 — סריקה אמינה (P1–P11)
- **B1** `financials.py`: ניסיונות מוגבלים, מניה שנכשלה מסומנת ולא תוקעת את הריצה; כל ריצה
  כותבת לתיקייה משלה (פותר P1 בלי "resume" שבור); resume רק בתוך אותה ריצה.
- **B2** `auth.py`: login אחד, headless, עוגיות ב-`DATA_DIR`.
- **B3** `screener.py`: pagination חסום במספר עמודים וזמן; dedupe סדרות; תיעוד הסינון (D7).
- **B4** `jobs/pipeline.py` + `cli.py run`: סדר נכון (סיווג אחרי הורדה), בלי `input()`,
  סיכום ok/failed. אימות: ריצה מלאה מקומית מקצה לקצה, בלי מגע יד.

### שלב 2 — מנוע הקריטריונים (R1–R13, K1–K3; תלוי בהחלטות D1–D9)
- **C1** `criteria.py` + `thresholds.py` + `statements.py`.
- **C2** סיווג מחדש (K1–K3, D6).
- **C3** סינון ראשוני ומשני (שיעור 3).
- **C4** גראהם (שיעור 4) — כולל שנת הפסד, תמחור Current.
- **C5** פישר (שיעור 5) — צמיחה YoY, שולי רווח 5Y, NA במקום PASS, שלילי ≠ עובר.
- **C6** פיוטרוסקי (שיעור 6).
- **C7** ציון; **C8** הזדמנות.
- **C9** דוח השוואה ישן↔חדש לכל 140 המניות: כל הבדל ממופה לממצא בביקורת או להחלטה.
  הבדל בלי הסבר = באג.

כל קריטריון מקבל טסט עם ערכים בדיוק על הסף, מעליו, מתחתיו, חסר, ושלילי.

### שלב 3 — אחסון
- **D1** סכמת SQLite, repository, retention, מיגרציה פשוטה (גרסת סכמה בטבלה).

### שלב 4 — אתר
- **E1** FastAPI + התחברות בסיסמה (env) + layout: RTL, טוקני צבע, מצב כהה, מובייל.
- **E2** מסך ראשי: כרטיסי סיכום, פיזור איכות↔הזדמנות, מטריצת קריטריונים, סינון לפי סקטור/סיווג.
- **E3** דף מניה: כל קריטריון (ערך, סף, מד מרחק), מגמות 5 שנים, פירוק ההזדמנות.
- **E4** מסך ריצות והגדרות: N ימים, "הרץ כעת", סטטוס חי, לוג, היסטוריה.
- **E5** scheduler + נעילה + התאוששות מריצה שנקטעה.

אימות: הרצה מקומית ומעבר ידני בכל מסך ובכל כפתור, כולל מצב כהה ומסך צר.

### שלב 5 — פריסה
- **F1** Dockerfile + healthcheck; בדיקה מקומית ב-`docker run`.
- **F2** Railway: שירות, Volume ב-`/data`, משתני סביבה, דומיין. ריצה ראשונה מהשרת.
- **F3** תיעוד סופי, מחיקת קבצי התוכנית.
